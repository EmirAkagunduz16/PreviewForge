# M1 completion and local tooling resolution

## Context

The remaining durable control-plane work covered deployment compare-and-set transitions, atomic deployment intent/outbox persistence, and a mandatory PostgreSQL integration-test gate. Two local workflow blockers also remained: PreviewForge inherited the unrelated parent Desktop repository and the selected Docker Desktop context pointed to an unavailable socket.

## Verified finding

- Deployment transitions now enforce the executable state map, expected status, desired SHA, terminal no-rewind, stale supersession, redacted failure persistence, and an outbox row in the same transaction.
- Deployment intent validates the versioned boundary, verifies environment ownership metadata and desired SHA, atomically writes its deterministic outbox event, and safely handles exact duplicates, conflicting identities, rollback, and concurrent attempts.
- The former recursive Vitest CLI glob matched no integration files under Vitest 5. The corrected direct-file glob runs both PostgreSQL suites.
- Local infrastructure commands now select the project-scoped `default` Docker context unless explicitly overridden. The global Docker context remains unchanged.
- The PostgreSQL 18 image stores `PGDATA` below `/var/lib/postgresql/18/docker`; mounting the former `/var/lib/postgresql/data` path left the actual database in an anonymous volume. The named volume now mounts `/var/lib/postgresql` so schema/data survive container recreation.
- PreviewForge now has its own Git root on `main`; it deliberately has no remote until a dedicated repository is selected.

## Evidence

- `DATABASE_URL=<local redacted value> pnpm check`: 15/15 Turbo tasks and 19/19 PostgreSQL integration tests passed on 2026-09-13.
- `pnpm run doctor`: Node, pnpm, Docker client, kubectl, Docker daemon, and Compose checks passed; daemon context was `default` and server version was 29.8.0.
- `pnpm infra:down` followed by `pnpm infra:up`: PostgreSQL, Kafka, and registry were recreated and reached healthy status.
- PostgreSQL inspection reported `PGDATA=/var/lib/postgresql/18/docker` and image volume `/var/lib/postgresql`; after correcting the mount, a second recreate retained the applied migration.
- `git rev-parse --show-toplevel` resolved to the PreviewForge directory and the branch resolved to `main`.

## Impact / consequences

M1 meets its acceptance criteria and M2 can consume the persisted deployment intent without changing the M1 concurrency model. Local infrastructure commands no longer depend on the user's broken global Docker Desktop selection. A PreviewForge remote remains an explicit maintainer choice and must not reuse the parent FlowOps remote.

## Prevention / next action

Create the first local commit, verify local history, and add a dedicated remote only after its URL is intentionally selected. Start M2 by adding stable backlog slices before implementation.
